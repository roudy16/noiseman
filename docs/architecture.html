Architecture · noiseman

How noiseman makes noise

A small background daemon owns the audio. The CLI, TUI and optional GUI control it by sending text lines over a Unix socket. The noise itself comes from one dependency-free Rust crate that also compiles to a 6 KB WebAssembly module for the browser demo.

The whole system

noiseman has two halves and one shared core. Frontends never import backend code: everything they know about the player arrives as state or err lines on the socket. Both the daemon and the web demo generate samples from noiseman-core, so every noise kind sounds the same in both.

Inside the daemon

One player thread owns all playback state and handles messages one at a time from a single channel. Per-client socket readers parse incoming lines (answering syntax errors directly) and forward valid commands to that channel; the audio error path posts AudioLost to the same channel. The audio callback never takes a lock: it reads the requested kind and gain from two atomics once per buffer and renders every frame with its own Voice.

Playing, fading, muted

Muting does not cut the stream at once. The target gain drops to zero and fades smoothly (τ = 10 ms, reaching silence within 100 ms), then the player waits for three device buffers to drain before dropping the stream. Once muted with no clients connected, the daemon is completely idle: two threads (main and accept) and zero wakeups.

The sound core

noiseman-core has no dependencies, does no I/O and never allocates. Noise turns a xorshift64 generator into five colours of noise, each scaled to about −18 dBFS RMS. gain(vol) maps volume 0–100 on a square law, and Voice smooths every gain and kind change with a one-pole fade (τ = 10 ms).

WhiteFlat spectrum: the raw generator.
Pink−3 dB/octave, Paul Kellet's refined filter.
Brown−6 dB/octave: a leaky integrator with a 15.3 Hz corner.
Blue+3 dB/octave: pink, differentiated.
Violet+6 dB/octave: white, differentiated.

The protocol

One request per line, one reply per request. Every reply is either a state line or an err line. After watch, the daemon also pushes a state line whenever anything changes; that is how the TUI and GUI stay in sync with each other and with the CLI.

# → request          ← reply
status               state brown 50 playing
kind pink            state pink 50 playing
vol +5               state pink 55 playing
mute                 state pink 55 muted
vol loud             err bad volume "loud"
watch                state pink 55 muted
                     state pink 55 playing   # pushed when another client unmutes

The other requests are vol N, vol -N, unmute, toggle and quit. An audio failure is appended to the state line as an error message, and the daemon reports itself muted.

In the browser

The web demo wraps noiseman-core in a raw WASM module with two exports (synth_init and synth_render) and no wasm-bindgen. The synth lives in static memory, so the module has no heap and stays near 6 KB. After setup, the page only sends the worklet two numbers: kind and vol.
