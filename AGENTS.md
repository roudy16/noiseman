# noiseman

Noise generator: a dependency-free sound core (`crates/core`), a headless player daemon (backend) and frontends that control it over a Unix socket: CLI, crossterm TUI, and an optional winit/softbuffer window with tray (`--features gui`). The core also runs in the browser (`web/`). Spec: `DESIGN.md` (see its revision notes).

## Verbs

`just setup | build | test | run | install | install-gui | clean`, plus `just fmt`, `just lint` (clippy, `-D warnings`, default and `--features gui`) and `just check` (fmt check, lint, tests, all workspace crates, then `just gates`; lint also runs clippy for the wasm target): run `just check` before committing. `just install` installs the terminal build, `just install-gui` the one with `gui`. `just gates` (`tools/gates.py`, ~2 s after the release builds) checks artifact sizes, DSP ns/sample, and the daemon's memory, threads, CPU and wakeups playing and muted, plus TUI and CLI memory, against `gates.toml`; it runs a private daemon (`daemon --muted`, then `vol 0` + `unmute`: a real stream, silent) and skips the runtime gates without a PulseAudio server. A change that needs a higher limit raises it in `gates.toml` in the same commit, with the reason. On Windows, `just gates-windows` is the counterpart. CI (`.github/workflows/ci.yml`, on pushes to main and pull requests) runs `just ci` on Linux: fmt check, lint, tests and only the size gates (`gates.py --sizes-only`), since timing and runtime gates mean little on shared runners; macOS and Windows run clippy (default and `gui`) and the tests of the root package and core (with `gui`). `just web` builds the demo into `target/web`; `just web-serve` serves it on :8000. Releases: push a tag `vX.Y.Z` that matches `Cargo.toml`'s version and `.github/workflows/release.yml` runs `tools/package.sh TARGET` and `tools/package.sh TARGET gui` (`just package [target] [variant]`), in one job per target, for x86_64/aarch64 Linux (in an `ubuntu:22.04` container: built against glibc 2.35, the binaries need 2.34, the version of the newest glibc symbols they import, which the README states; check with `objdump -T`), x86_64/aarch64 macOS (minimum macOS 11: `MACOSX_DEPLOYMENT_TARGET`) and x86_64/aarch64 Windows, then publishes the archives, their `.sha256` files, `tools/install.sh` (the `curl | sh` installer) and `tools/install.ps1` (the Windows `irm | iex` one) as a GitHub release. Each target has two archives (`.tar.gz`, `.zip` for Windows): `noiseman-<target>`, the terminal build (default features), and `noiseman-gui-<target>`, built with `gui`; the binary is `noiseman` in both, so they are alternatives installed at the same path. Each holds `LICENSE`, `README.md` and `THIRD-PARTY-LICENSES.txt` (`tools/licenses.py TARGET [gui]`: that variant's crates), plus on Linux `share/` (icons, a desktop entry from `assets/noiseman.desktop`: the gui build's runs `noiseman gui`, the terminal build's, made with a `sed`, runs `noiseman` in a terminal) for `install.sh`, and in the gui build on Windows `noiseman-gui.exe`: the same program linked for the Windows subsystem (no console; run under that name with no arguments it opens the window), which the Start menu shortcut runs (without it, the shortcut runs `noiseman.exe`: the TUI in a console). Both installers fetch the terminal build, or the gui build with `NOISEMAN_GUI=1`. `install.ps1` installs per user to `%LOCALAPPDATA%\Programs\noiseman`, with an `nsm.exe` hard link, a user PATH entry (edited in place in the registry, keeping it `REG_EXPAND_SZ`), the shortcut and a Settings > Apps entry whose Uninstall runs the `uninstall.ps1` it writes; install and uninstall touch only the files the installer wrote (the PATH entry only if it added it, the directory only once empty), so `NOISEMAN_INSTALL_DIR` may be a shared directory. `build.rs` embeds `assets/noiseman.ico` and version info on Windows; `uv run tools/icons.py` draws the .ico, `assets/noiseman.svg` and the PNGs (16-256 px) from one layout: the brown theme's tile with the first six bars of the UIs' logo, pixel-snapped per size; `install.ps1` tells its own `nsm.exe` apart by that product name. `[package.metadata.binstall]` in `Cargo.toml` points cargo-binstall at the terminal build's archives; keep the asset names in step with it and with both installers. Formatting: `rustfmt.toml` (120 columns, `use_small_heuristics = "Max"`).

## Layout

Cargo workspace: the root package `noiseman` (the binary), `crates/core` and `web`.

- `crates/core/` (`noiseman-core`; no dependencies, no I/O, no allocation)
  - `src/lib.rs`: `Kind` (labels, `from_u8`, `parse`), `gain(vol)` (square law)
  - `src/noise.rs`: `Noise` generators, the one level/bounds test
  - `src/voice.rs`: `Voice::new(rate, seed, kind)` and `step(kind, gain)`: 10 ms gain fade, kind change via silence; its test
  - `examples/noise_profile.rs`: DSP benchmark (`Voice::step`, as the daemon and the wasm run it) for `just profile` and the DSP gate
- `src/main.rs`: `daemon [--muted]` runs `backend::serve`; everything else goes to `frontend::run` (run as `noiseman-gui` with no arguments: `gui`)
- `build.rs`: on Windows, embeds `assets/noiseman.ico` and version info (`winresource`)
- `src/protocol.rs`: the only contract between the halves: `Kind` (re-exported from core), `Command`, `State`, their line encoding (`protocol` gets its own reply: `protocol_reply`, `parse_protocol`), `PROTOCOL` (the protocol's own semver, bumped with any protocol change) and `compatible()`, `runtime_dir()` (from `platform`) and `socket_path()`, round-trip test
- `src/platform/` (shared by both halves; the only OS-specific code)
  - `mod.rs`: the contract both backends meet, and a test that `net` behaves as the backend and client need (concurrent read and write, write timeout, shutdown EOF, a removed socket file)
  - `unix.rs`: runtime dir (0700, uid check), `setsid`, chmod 0600, std's `UnixListener`/`UnixStream` (truecolor comes from `COLORTERM` alone)
  - `windows.rs`: runtime dir, detached spawn, console truecolor check (Windows Terminal and conhost set no `COLORTERM`), `alert_if_no_console` (`gui`: a message box for errors when stderr goes nowhere, as for `noiseman-gui.exe`), `UnixListener`/`UnixStream` over AF_UNIX (Windows 10 1803+; std lacks them there)
- `src/backend/` (no frontend imports)
  - `mod.rs`: `log!` (every line the daemon writes: UTC timestamp, `utc()` with its test; the first says version and protocol), `serve()`: lock file, socket (`platform::net`), then leaves the starting directory for the runtime dir, accept thread, one reader thread per client, the player loop (`mpsc` + `recv_timeout`), watcher broadcast, fade-out on quit
  - `player.rs`: `Player`: volume, mute, stream lifetime (drop after fade), audio-lost restart, `State`
  - `audio.rs`: `GAIN`/`KIND` atomics (private; `kind()`, `set_kind()`, `set_gain()`), `AudioError`, `start()` returning `Output` (`buffer_time()`; on Linux the PulseAudio host, then ALSA, failing as `NoPulse` so the error names the missing server), `build::<T>()`, data and error callbacks (a core `Voice` per stream)
- `src/frontend/` (no backend imports)
  - `mod.rs`: argument dispatch (none/`tui`, `gui`, `help`, `version`, else CLI)
  - `client.rs`: `Client { sender, receiver, warning, started }`, `connect(autostart)` (asks an already-running daemon its `protocol`; `warning` when incompatible), daemon autostart (`platform::spawn_detached`, log to the runtime dir)
  - `cli.rs`: subcommands and `USAGE`; a command that asked for sound (or started the daemon) and left it muted by an audio error exits 1
  - `tui.rs`: crossterm screen (refuses to start without a terminal); one thread reads keys, one reads pushed states, the main thread draws
  - `gui/mod.rs`, `gui/tray.rs` (`gui` feature): the window and ksni tray as a protocol client
- `web/` (`noiseman-web`, cdylib for `wasm32-unknown-unknown`)
  - `src/lib.rs`: `synth_init(rate, seed, kind)`, `synth_render(kind, vol, frames) -> *const f32` over one static synth; no wasm-bindgen, no heap
  - `site/`: `index.html`, `style.css`, `app.js` (controls, keys, localStorage, AudioContext lifecycle), `worklet.js` (AudioWorkletProcessor calling the wasm)

## Invariants

- Frontends reach the backend only through `protocol` over the endpoint, never by import; the backend never imports `frontend`.
- Any change to the protocol bumps `protocol::PROTOCOL` by semver (independent of the app version): an addition clients may rely on bumps the minor, any other change the major (while the major is 0: the patch and the minor), as `compatible()` reads them.
- Audio data callback: no allocation, locks, logging or syscalls. It reads `KIND`/`GAIN` once per buffer (`Relaxed`).
- Player thread: blocks in `recv` (or `recv_timeout` only while a mute fade is pending). Muted means no stream and 0 wakeups; the daemon then has 2 threads plus one per connected client.
- Client writes use a 200 ms timeout so a stalled client cannot stall the player; a watcher whose write fails is dropped.
- One daemon per user: `noiseman.lock` (`File::try_lock`) is held for the daemon's life, so a socket file found while holding it is stale and removed.
- Error callback (not RT) logs, and on `DeviceNotAvailable | StreamInvalidated` sends `AudioLost` to the player thread, which restarts the stream.
- Default state: brown, volume 50, playing. Quit mutes and waits for the fade before exiting.
- cpal uses the `pulseaudio` backend on Linux (CoreAudio on macOS, WASAPI on Windows); the default format is the sink's own (I32 on the PipeWire pulse server here), so keep the `SampleFormat::I32` arm alongside the others.
- `crates/core` stays dependency-free and I/O-free; both the daemon and the web demo get their sound only from it, so they sound the same.
- `docs/architecture.html` is the illustrated explainer, published at `/architecture/` by `just web`; update its diagrams and numbers when threads, states, the protocol, the fade or the gate baselines change.
- Web: the worklet does no allocation per block (cached `Float32Array` view); the page suspends the AudioContext after a pause; the wasm has no heap. Keep the module small (check its size after `just web`).
- Every noise type is normalised to about -18 dBFS RMS; the test enforces ±1.5 dB.
- Release profile uses `panic = "abort"`; never let a panic reach the callback. The TUI restores the terminal from a panic hook.
- GUI (Linux tray): closing the window hides to tray (drops window and surface); with no tray, closing quits and stops the player. Tray callbacks only `send_event`; zbus calls stay off the winit thread. The window is sized to `WIN_W` x `WIN_H` times the whole scale nearest the OS scale factor (`window_size`), at open and on `ScaleFactorChanged`, so `paint` fills it. ksni uses `blocking` + `tokio`.
- Dependencies: noiseman-core, cpal, crossterm, libc (Unix), windows-sys (Windows); with `gui`: winit, softbuffer, font8x8, ksni (Linux). Build: winresource (Windows, no default features). No GPU, no toolkit.
- Platform code lives only in `src/platform/`: `mod.rs` states the contract (`runtime_dir`, `restrict_to_owner`, `spawn_detached`, `terminal_truecolor`, `net::{UnixListener, UnixStream}`, with `gui` `alert_if_no_console`), `unix.rs` and `windows.rs` implement it with the same signatures. Nothing else names `std::os::*`, `libc` or `windows_sys`. Both OSes use `noiseman.sock` in the runtime dir. Unix: std's Unix sockets, the file 0600 in a 0700 dir, `setsid`. Windows: AF_UNIX (Windows 10 1803+) through a small copy of std's API in `windows.rs` (delete it once std has one); the socket file inherits the dir's ACL, and the dir is `%LOCALAPPDATA%\noiseman` (user, SYSTEM and admins only) or `$XDG_RUNTIME_DIR`, which must be private just as on Unix; paths are UTF-8 and under 108 bytes; sockets are overlapped, so a blocked read never blocks the player's write; the daemon is spawned detached in its own process group, out of the caller's job when the job allows. On Windows run `just` from Git Bash (recipes use `sh`); the runtime gates read `/proc`, so they run on Linux only and SKIP elsewhere; on Windows `just gates-windows` (`tools/winperf.ps1`, limits in `gates.toml` `[windows]`) gates the same things, counting only noiseman's own threads (Windows adds thread-pool, COM and WASAPI threads).
- `just deps` (`tools/deps.py`, network) reports advisories for every locked crate (OSV, which mirrors RustSec) and drift of direct dependencies and vendored crates from crates.io's latest stable (via the sparse index); it fails only on a vulnerability. Run it before upgrading or vendoring. Known informational advisories (2026-11-24): unmaintained `ttf-parser` (winit's decorations) and `zbus_names`/`zvariant`/`zvariant_derive` (ksni), all `gui`-only, no fix upstream yet.
- Licenses: our crates are MIT (`LICENSE`, `license = "MIT"`). New dependencies must be permissive (no GPL/LGPL/AGPL/MPL); check with `cargo tree --features gui --target all -e normal,build -f '{p} {l}'`.
- Vendored crates, wired in via `[patch.crates-io]`; re-apply or drop each change when upgrading. Keep each crate's LICENSE file, and the "Modified by noiseman" header at the top of every changed file, `Cargo.toml` included (Apache-2.0 §4(b) for cpal):
  - `vendor/pulseaudio`: pulseaudio 0.3.2 (pruned to `src/`, `Cargo.toml`, `LICENSE.md`; `Cargo.toml` stripped of readme, examples and dev-dependencies so the pruned crate builds) with three code changes: in `client/reactor.rs`, `Reactor::recv` reads in 64 KiB chunks instead of zero-filling 1 MiB per read, and `handle_command` removes a stream on `PlaybackStreamKilled` (upstream ignored it, so a server-killed stream was never reported and dropping it hung); in `lib.rs`, `socket_path_from_env` finds the server where libpulse does (upstream issue #24): `$PULSE_SERVER` alone when set, else the first of `$PULSE_RUNTIME_PATH/native` and `$XDG_RUNTIME_DIR/pulse/native` that exists (upstream stopped at the first missing location and looked for `$PULSE_RUNTIME_PATH/pulse/native`). Its unit test (`socket_path_test`) needs the stripped dev-dependencies to build with the rest of the crate's tests.
  - `vendor/cpal`: cpal 0.18.2 (pruned to `src/`, `build.rs`, `Cargo.toml`, `LICENSE`; `Cargo.toml` stripped likewise) with two code changes: in `host/pulseaudio/stream.rs`, the playback latency thread no longer wakes per write or every 100 ms, only on play/pause/drop, so `OutputCallbackInfo` timestamps go stale (noiseman ignores them); in `host/pulseaudio/mod.rs`, `Device::Sink` has `is_default` (set only by `default_output_device`), and a stream on the default sink is created with no sink index, so the server moves it when the default output changes (PipeWire pins a stream created with an index); enumerated sinks stay pinned.
